## 现在做什么

保留现有MCP、CSTClient、任务监督、读回、导出与全部证据。先由Codex核对本地工件、实际FDTD/PiDeck和CST入口，评估新要求、补齐文件级实施方案；无重大分歧则在既有授权内继续实现正式工作台。

优先补：项目/会话/工程/模型修订/运行绑定，中央3D/原理图/结果，手动属性及运行控制，人工与Agent交接。真实网格出口单独验证，不以STL线框或单元数代替。222资源问题只阻塞对应重运行，不阻塞其模型/原理图/配置界面和其他工作区开发。

当前结果网页按工程路径收集曲线、远场run_id使用文本标识；正式工作台需补真实运行/修订归属。上述是风险识别，不断言既有独立副本结果全部错误。详见W1。

## 用户只需验收什么

**打开选定案例 → 切3D/网格/原理图 → 手动改参数 → Pi读到新值 → 手动运行看结果 → Pi再修改/运行 → 工作区同步 → 保存重开。**

内部小测试由Codex决定并归档，不要求用户逐项选。偶极子先完成此交互，222继续完成新V/I；只读页面、空壳工作区或固定脚本通过不能替代完整交付。流程、数值、实际窗口和人工验收分别记录。
