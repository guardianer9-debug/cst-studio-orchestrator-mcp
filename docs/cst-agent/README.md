## 核心方向

**Pi Agent + PiDeck + 现有 CST MCP；代码优先，可靠封装复用，统一执行和验证。**

Pi 负责需求理解、必要补问、查询资料、编写/修改 Python 或 VBA、解释依据。MCP 是接入通道，不是智能体本身；其后端负责工程身份、权限、执行、状态、读回、日志和结果。CST 保留几何、原理图、网格、求解和后处理职责。PiDeck 展示实际工程的可视化副本，不另建竞争模型真源。

长期追求广泛功能覆盖，短期同时验证一个 3D 小案例和一个原理图小案例。两者都纳入架构，不把原理图推迟到天线平台做完之后。与既有 FDTD 工作线隔离开发，复用交互经验，不改其生产目录和全局配置。

## 更新规则

主方案始终维护同一路径，不创建多个同时声称“最新”的总方案。每轮在 `review-log.md` 追加记录，标明审查输入提交、文档版本、依据、修改和未决事项。旧文本由 Git 历史保留，失败/实验原始证据不得覆盖。聊天用于传达结论，不能替代仓库中的设计与证据。

建议循环：**ChatGPT R0 → Codex 核验并修订 R1 → ChatGPT 核验提交并复核 R2 → 项目负责人确认设计基线 → 分里程碑实施。** 这是人工触发的交接，不是已经安装的自动审查服务。

只有影响核心可行性、安全边界或当前交付范围的未决问题阻止设计冻结；远期能力和必须通过实机验证的问题进入对应里程碑，不无限延长纸面讨论。审查一致不等于功能通过。
