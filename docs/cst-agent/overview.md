# CST Agent 简化版：整体架构与当前开发顺序

依据：详细方案 R1（0.2.0），提交 `887417cc53383cbc71245993831ed40049bf1b5c`。整理日期：2026-09-20。

本文是详细方案的通俗导览，不是一套新技术方案，也不表示功能已经实现。具体接口、约束和验收以[详细方案](architecture-and-delivery-plan.md)为准。

## 1. 我们最终要做什么

做一个类似现有 FDTD Agent 的 CST 工作台：你在 PiDeck 里输入需求、查看模型、对话修改、运行仿真、查看结果。Pi 负责理解和组织代码，现有 MCP 及其后端负责操作 CST。3D 和原理图都要支持，再逐步扩展到天线、线缆串扰、腔体和车辆线缆。

目标是逐步让常用工作流不必手动打开 CST 界面，不是现在就宣称所有按钮都已被替代。

## 2. 整体架构

```text
你：描述需求、确认条件、提出修改
                  ↕
PiDeck：聊天 + 3D/原理图 + 参数/依据 + 运行/结果
                  ↕
Pi Agent：理解需求 → 查官方资料/已有示例 → 组织 Python/VBA
                  ↕
现有 MCP + 统一 CST 控制后端
确定目标工程 · 执行操作 · 读取实际值 · 保存 · 管理仿真任务
                  ↕
CST：3D建模 / 原理图 / 网格 / 求解 / 后处理

CST 的实际工程数据和结果 → 返回 PiDeck 展示，并供 Pi 检查
```

图中是职责分工，不是要求新建五套软件。PiDeck 的保存、运行、停止按钮也调用同一控制后端，不必先问一次大模型；按钮和 Pi 不能各自打开一套互不知情的 CST 控制会话。

| 部分 | 通俗理解 |
|---|---|
| PiDeck | 你使用的界面：看、问、选择、修改、看结果。 |
| Pi Agent | 理解需求，查资料，编写和修改操作代码，解释参数依据。 |
| MCP 与控制后端 | 把操作送到正确工程，确认是否生效，返回实际数据。 |
| CST | 真正建立模型、电路、网格并计算结果。 |

## 3. 到底是填参数还是写代码？

**两者结合，不二选一。**

常用、已经验证的操作继续复用封装；复杂组合和未单独封装的功能保留 Python/VBA 编程路径。MCP 是调用通道，不能变成只允许填几个模板的限制。

R1 只是把第一包收小：先复用已有工具、Python 参数/脚本组织能力和明确的 3D/原理图执行入口，不先建设“可安全执行任意 Python”的沙箱。**暂不做任意代码执行平台，不等于放弃代码优先。**

例如修改一个尺寸，软件不能只回答“已设置为 12 mm”，还应从 CST 读取几何，确认它实际变为 12 mm。原理图也一样，必须读回真实元件属性与引脚连接，不能只把提交的参数原样返回。

## 4. 当前按什么顺序开发

| 阶段 | 做什么 | 做完不代表什么 |
|---|---|---|
| **P1A：正确操作与读回** | 一个参数化长方体 + 一个 RLC 原理图网络；确认工程绑定、修改、实际值、连接、保存恢复及错误处理。 | 不是完整 Agent/UI，不包含网格或求解。 |
| **P1B：真实运行与停止** | 用很小的 3D 和原理图任务验证启动、状态、停止及故障；分别确认两个域。 | 一个域通过不代表另一个域通过，也不代表数值正确。 |
| **CST-2/3：可用的交互工作台** | 接入 Pi 和 PiDeck；完成自然语言建模、多轮修改、参数依据、显示、授权运行和结果。 | 不能据一个案例声称覆盖全部 CST。 |
| **CST-4/5：领域与功能扩展** | 偶极子基础上扩线缆串扰、小腔体、STEP/车辆，再逐项完善功能清单。 | 未测试功能仍明确列为未验证。 |

局部显示可以在相关后端功能稳定后开始，不必等所有接口完成；真实运行按钮必须等对应控制链验证，不交付“点了停止但求解还在继续”的假功能。

## 5. 第一包具体交付什么

**3D 案例：** 毫米单位、PEC 长方体，L=10、W=5、H=2；改 L 到 12，再改 W 到 6。验证实际尺寸、材料、表达式和单位，保存后重新打开核对。

**原理图案例：** R=50 Ω、L=10 nH、C=1 pF，加入外部端口、参考节点及明确的引脚连接；改 R 到 75 Ω，再改 C 到 2 pF。验证真实属性、单位和连接，保存后重开核对。不创建会触发运行的任务。

两个案例还要证明：不会操作错工程；旧版本请求被拒绝；重复请求不会重复创建；错误或读取不到时不会报成功。原理图必要属性或参考节点读不到，就保留阻塞，不能降成“元件数对了就通过”。

第一包用固定程序测试，不调用产品 Pi/模型服务，不生成网格、不求解。真实 CST 的建模和保存测试需要在已批准的专用副本与预算内进行；无连接协议测试不得启动 CST。验收材料应包含小工程、修改前后读回、测试记录和缺口，不只是完成总结。
