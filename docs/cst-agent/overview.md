## 1. 最终要做的是什么

不是“智能体做完后给我一张结果网页”，而是**一个类似FDTD版PiDeck、比原生CST简化的工作台**。

你可以自己查看模型、改参数、设置任务、点击运行和看结果；也可以让Pi帮你做。你操作完，Pi能接着操作；Pi修改完，界面能同步显示。两者用的是同一个实际工程，不各做一套。

## 2. 整体架构

```text
PiDeck：项目/聊天 + 中央工作区 + 右侧工作台
          │                        │
     你手动点按钮             你让Pi去做
          │                        │
     桌面控制入口        Pi查资料、组织代码、调用MCP
          └───────────┬────────────┘
                  同一CST控制后端
        工程绑定 · 实际修改与读回 · 保存 · 运行/停止
                       ↕
       CST：3D / 原理图 / 网格 / 求解 / 后处理
                       ↓
         实际模型、参数、作业和结果回到工作区
```

手动运行、停止、保存和查看已有结果不需要大模型在线。MCP是操作通道，代码是灵活组合动作的方法；常用操作继续复用已有封装，不推翻现有工作。

## 3. 界面应该怎样用

| 区域 | 你能做什么 |
|---|---|
| 项目与聊天 | 选工程/案例、提需求、追问依据；聊天可收起让模型区域变大 |
| 3D模型 | 旋转、放大、隐藏/透明、选择实体、查看和修改当前案例属性 |
| 真实网格 | 看实际求解网格、截面和设置；不是把STL模型画成线框 |
| 原理图 | 看元件/引脚/负载/地/探针/连接；选择元件并修改当前案例属性 |
| 结果 | 选本次或历史运行，查看S11、方向性切面，后续查看222电压电流 |
| 工作台与工具条 | 打开/保存、刷新实际状态、任务/求解设置、网格、运行、停止、日志 |

布局沿用FDTD工作台的习惯，内容按CST特点组织。不必复制CST每一个按钮，也不要求第一版就做出全套鼠标CAD和器件拖拽编辑器。正式工作区不是右侧浏览器打开的独立结果页。

## 6. 你最终怎样验收

打开偶极子，在工作区看模型和结果，手动改一个参数；让Pi读出新值；点击运行；查看新结果；再让Pi修改一次，确认界面跟着更新。最后保存、重开，仍能继续。

222同样要能核对腔体、线缆、两端负载、探针和task；新完整V/I没出来之前明确保持未完成。
