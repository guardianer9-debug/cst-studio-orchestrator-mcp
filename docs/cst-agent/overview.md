## 1. 我们最终要做什么

做一个类似现有 FDTD Agent 的 CST 工作台：你在 PiDeck 里输入需求、查看模型、对话修改、运行仿真、查看结果。Pi 负责理解和组织代码，现有 MCP 及其后端负责操作 CST。3D 和原理图都要支持，再逐步扩展到天线、线缆串扰、腔体和车辆线缆。

目标是逐步让常用工作流不必手动打开 CST 界面，不是现在就宣称所有按钮都已被替代。

## 2. 整体架构

```text
你：描述需求、确认条件、提出修改
                  ↕
PiDeck：聊天 + 3D/原理图 + 参数/依据 + 运行/结果
                  ↕
Pi Agent：理解需求 → 查官方资料/已有示例 → 组织 Python/VBA
                  ↕
现有 MCP + 统一 CST 控制后端
确定目标工程 · 执行操作 · 读取实际值 · 保存 · 管理仿真任务
                  ↕
CST：3D建模 / 原理图 / 网格 / 求解 / 后处理

CST 的实际工程数据和结果 → 返回 PiDeck 展示，并供 Pi 检查
```

图中是职责分工，不是要求新建五套软件。PiDeck 的保存、运行、停止按钮也调用同一控制后端，不必先问一次大模型；按钮和 Pi 不能各自打开一套互不知情的 CST 控制会话。

| 部分 | 通俗理解 |
|---|---|
| PiDeck | 你使用的界面：看、问、选择、修改、看结果。 |
| Pi Agent | 理解需求，查资料，编写和修改操作代码，解释参数依据。 |
| MCP 与控制后端 | 把操作送到正确工程，确认是否生效，返回实际数据。 |
| CST | 真正建立模型、电路、网格并计算结果。 |

## 3. 到底是填参数还是写代码？

**两者结合，不二选一。**

常用、已经验证的操作继续复用封装；复杂组合和未单独封装的功能保留 Python/VBA 编程路径。MCP 是调用通道，不能变成只允许填几个模板的限制。

继续复用已有工具、Python参数/脚本组织能力和明确的3D/原理图执行入口，不先建设“可安全执行任意Python”的沙箱。按用户新要求，开发范围以真实案例完整复现为目标；小步骤用于内部定位问题，不再作为做完就暂停的对外交付。

例如修改一个尺寸，软件不能只回答“已设置为 12 mm”，还应从 CST 读取几何，确认它实际变为 12 mm。原理图也一样，必须读回真实元件属性与引脚连接，不能只把提交的参数原样返回。

## 4. 当前按什么顺序开发

| 阶段 | 做什么 | 做完不代表什么 |
|---|---|---|
| **P1A：内部模型与配置检查** | 直接围绕222孔缝腔体线缆及官方例，打通3D、线缆、原理图、任务设置和实际读回；必要时用砖/RLC定位问题。 | 不能停在小测试通过就说交付完成。 |
| **P1B：内部运行控制检查** | 以小任务核对启动、状态、停止和故障，解决后继续同一案例。 | 不因包编号变化重复等用户说“继续”；不把请求取消当真实停止。 |
| **CST-2/3：整案例交付** | 同一Pi在PiDeck完成案例建模、修改、运行、结果和解释；持续修复到222裁剪例及已选官方例通过完整验收。 | 一个工具、模型截图或固定脚本通过不等于完整产品复现。 |
| **CST-4/5：更广扩展** | 继续未纳入本批的复杂布线、其他腔体/车辆及更多功能。 | 222主例不等待本阶段；不承诺尚未验收的全部CST功能。 |

局部显示可以在相关后端功能稳定后开始，不必等所有接口完成；真实运行按钮必须等对应控制链验证，不交付“点了停止但求解还在继续”的假功能。

## 5. 当前交付终点是什么

**第一主例：222孔缝腔体内线缆耦合。** 参考用户指定工程，保留孔缝腔体、平面波HPM、内部线缆、两端电阻接地和探针，并自动创建/设置task、配置求解器及必要网格/监视。排除天线与port3，同时处理原理图端子、激励和结果引用，不能只在三维视图里隐藏天线。

**官方案例：** 偶极子为必达主例之一，教程贴片、同轴传输、线束串扰与双绞线受照射按已选清单继续覆盖。官方模板/宏和已有MCP配方可以复用，不要求重新发明模型；但从空工程重建、打开模板操作和重新求解分别计验收。

**做到什么才算完成：** 能自动建立正确模型与电路/任务设置，读回核验，保存重开；能在同一PiDeck会话修改、解释当前参数；在明确的运行范围内执行仿真，取得与当前模型对应的V/I、S参数或方向图并按参考条件比较。失败时继续定位接口、设置、读回、运行和展示中的问题，而不是以“砖/RLC已通过”结束。

砖和RLC仍可使用，它们是开发者内部排错工具。检查点通过后连续推进到真实案例；同一批准范围内的修复复测不逐包请示。物理条件变化、资源预算扩大、许可/API的实际阻塞才集中沟通。

当前是方案讨论，未启动CST或产品Provider。旧玩具包的5分钟/30分钟/固定重试次数不作为222整案例的运行预算；真实范围与保护条件明确后再实施，已授权后持续推进。移除天线会改变物理模型，不能直接把含天线旧曲线作为裁剪版的逐点答案。
